# Живая оценка агентов L2/L3 · 2026-11-01

## Что измерялось

Контракт рантайма на настоящей модели Claude: валидность схемы с первой попытки, дословность цитат, происхождение замеров, бейджи, честность чисел, оценка Судьи.

**Не измерялось.**
- Клиническая верность выводов: эталонной разметки нет.
- Выбор инструментов: обязательные инструменты вызывались заранее, модель получала их результат.
- HTTP-транспорт: ключа API нет.
- Устойчивость к повтору: повторной попытки в замере не было, невалидный первый ответ считался невалидным.

## Метод

- **Модель.** Субагенты Claude Code с алиасом `sonnet`, по одному запуску на пакет, без права читать репозиторий.
- **Данные.** Три синтетических транскрипта (`t1` демо, `t2` горе и избегание, `t3` карьерный выбор). Реальных клиентских записей нет. В `t2` добавлены фиктивные телефон и e-mail: маскирование их заменило, в пакеты ушли метки.
- **Проверка.** Ответы принимает тот же `AgentRunner`, что и в продукте. Агенты зависят друг от друга, поэтому прогон шёл раундами.
- **Синтез.** Рефлектор шёл одной выборкой вместо трёх, поэтому консенсус не проверялся.
- **Воспроизведение.** `node scripts/live-eval.mjs report` пересчитывает отчёт из записанных ответов в `eval/live/`.

## Что нашли

Из 10 принятых с потерями запусков все потери связаны с якорями-замерами. Выдумок в цитатах нет.

1. **Ссылка на контейнер вместо значения (5 случаев).** Модель цитирует `lexisTool.modality.counts`. Это объект без значения, рантайм его отклоняет. Причина в промпте: модель не видит списка допустимых путей.
2. **Утверждение об отсутствии данных, привязанное к пустому замеру (4 случая).** Например «просодика недоступна» с якорем на `prosodyTool.f0.mean` или `cascadeEngine.drives`. Поведение честное, но по контракту отсутствие данных идёт в `limits`, а не в `claims`. Рантайм правильно отбросил такие утверждения.
3. **Ошибка пути (1 случай).** Ключ с точкой в имени спикера `К.` разбил путь.

Модель ни разу не выдумала цитату, не придумала замер и не завысила бейдж утверждения до принятого.

## Что исправить (не исправлено, чтобы не менять метрику задним числом)

1. В результат каждого инструмента добавить список допустимых листовых путей для якорей.
2. В преамбулу агентов добавить правило: «отсутствие данных пишется в limits, не в claims».
3. Экранировать точки в ключах спикеров в путях замеров.

После правок прогнать замер заново и сравнить с этим отчётом.

## Оговорки

- Судья детерминированный, он проверяет форму и якоря, а не смысл.
- Оценка Судьи 0,98 завышена самим устройством рубрики: потерянные утверждения в неё не входят.
- Три коротких синтетических транскрипта дают контрольную точку, а не статистику.
- Субагенты видели промпт и схему так же, как модель в продукте, но не использовали tool use. Поведение с настоящим вызовом инструментов не проверено.
